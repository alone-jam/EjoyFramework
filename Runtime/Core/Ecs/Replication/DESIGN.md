# Replication 设计

## 目标与非目标

先固定 M3 与 M4 的组件契约：复制模式、组件行为、稳定的外部 schema ID，以及冻结后不可变的目录。

当前包含契约目录、基线/插值/预测历史、组件成员代数校验、显式采集/恢复工具和只改值的重放；不选 UDP/TCP 或锁步/状态同步方案，不实现 codec 或通用多实体回滚协调。

## 依赖边界

- Core.Ecs：行为接口、目录元数据、值副本存储与显式采样/恢复边界。
- GamePlay.Netcode / M4：生成 codec、远程身份、包序列号和输入确认、快照拼装、量化差分、传输和重放策略。
- Core.Ecs 保持零程序集引用。内部 ComponentType ID 仅用于查找，绝不当作网络 ID。

## 当前设计决策

| 决策 | 理由 |
|---|---|
| 三种模式 + unmanaged 约束 | 阻止托管引用在快照间隐式共享；普通 ECS 组件仍允许 struct，不收紧原存储规则 |
| 非零 ushort 外部 ID | 明确注册契约，不把类型名或运行时首次使用顺序当作协议 |
| 单列表注册，冻结时生成索引 | 冷路径唯一性检查 O(N)，逻辑注册一次成功；不需要跨两个可分配字典回滚 |
| 按外部 ID 排序 | 相同注册集合不因顺序不同而产生不同描述顺序 |
| 只读描述与 volatile 冻结发布 | 所有数组构造完后才可读；冻结后无更新，不需要热路径锁 |
| 行为方法在值副本上调用 | 接口本身不能保证 struct 方法不修改 this；后续存储层必须保护保留的基线 |

参考 FPSSample 的 Replicated/Predicted/Interpolated 分类，不采用其反射扫描、类型名排序和每实体序列化器对象数组。

## 最新值存储（已实现）

AuthoritativeBaselineStore<T> 借用 World，以完整 Entity + 存储身份 + 时间线 + 绑定代数隔离值副本。每次访问还检查组件 membership lifetime，因此在两次访问之间移除重加也会自动使旧绑定失效，重新 Bind 后才接受新数据。标记只在 Add 时生成，值更新/预留不改变；稠密 swap-remove 搬移标记，扩容将所有数组准备完再发布。它带来每个稠密容量槽位 8 字节的开销，但避免观察者回调、重入和异常链。单类型平铺数组只保存最新值，不自动形成跨组件一致基线。

写入按普通 uint 大小比较（非回绕），拒绝重复和更旧 tick；时间线重置清空所有绑定。旧排队更新必须保留原绑定，不允许适配器把旧数据重新贴上新 token。修改操作遵循 World 结构安全点，读取仅返回副本；不会恢复或修改 World 状态。

## 状态一致性约束

1. 基线/历史拥有 T 的值副本，按完整 Entity 身份隔离，不能只用稠密位置或槽位下标。
2. 权威样本 tick 不得为 0；当前 TickClock 模拟 tick 不回绕，不能把 uint.MaxValue → 1 当作同一时间线的新样本。重连/重置必须显式清除或替换历史。
3. 权威基线拒绝重复和更旧样本；恢复要求明确、完整的一致基线 tick，不能混用各组件不同时间的“最新值”。输入确认序号与快照 tick 分开。
4. 插值：空历史返回失败；一个样本直接返回；早于最早夹到最早，晚于最新夹到最新；精确 tick 直接返回，否则按实际 tick 距离计算权重。重复 tick 不覆盖；保留窗口内乱序插入与权威基线更新是两个决定。
5. 实体销毁、组件移除重加、预测所有权转换、时间线重置都需要失效处理；不得向销毁中的实体恢复组件。
6. 本地渲染 Alpha 不等于远程两个快照间的权重。捕获必须有明确的完成 tick 边界；不能用 RunFrame 模拟重放。

基线、插值/预测历史与 lifetime 访问失效已实现。`IEcsTickCompletedSink` 提供每个完成 tick 后的采集边界，但不强制只读；采集者负责先填完整批次再发布。`ComponentStateTransfer` 提供立即执行的一/两组件精确 tick 恢复，预先校验全部目标后才写值。显式 Replay 保持真实时钟不变、拒绝结构操作，并检查自有缓冲不向正常帧泄漏命令。更大范围事务、统一远端时间线验证和完整纠错编排仍是后续工作。

## 封闭纠错示例（已实现，未运行验收）

[示例代码与契约](../../../../Samples~/EcsDemo/PredictionCorrection.md) 已按以下边界实现并完成静态审查，测试未编译或运行。

示例拥有封闭模拟范围：一个 World、一个预测实体、两个覆盖全部可变模拟状态的具体组件，配无状态可重放系统、固定配置、精确 tick 输入记录和双组件采集 sink。不要在 M4 尚未确定输入/会话/依赖所有权前包装成通用回滚协调器。

顺序必须是：

1. 只读预检：权威 epoch 与同一来源的成对基线、两个组件精确基线 tick 和当前 lifetime、两个预测锚点、整个重放区间的输入记录与 epoch、固定模拟范围和采集 sink、loop.ValidateReplay 的范围/预算/命令缓冲条件。即使最终两个预测都匹配，也应完成预检。
2. 任一前置缺失，返回显式的“需要重新同步、无修改”结果；不能用当前输入/零输入/邻近 tick 或插值补缺。
3. 两个组件均匹配时不恢复、不截断、不重放。任一个不匹配，则一次恢复两个组件，截断两份预测历史并记录两个权威锚点，然后重放、逐 tick 采集两份历史。每个返回结果都必须检查。
4. 恢复开始后的失败不是“无修改”：保留原异常、要求 owner 恢复，不自动 ResetClock，不声称之前值/历史已回滚。锚点重建发生在 Replay 前，故 owner 也必须有独立恢复标记。

**两个恢复目标不是两个目标的重放过滤器。** EcsLoop 会执行整个 World 中所有已启用且允许重放的 tick 系统。若它们还更新其他实体、随机数、系统内部状态或变化配置，这些依赖及其全部历史都必须一起预检、恢复和重建。封闭示例不暴露任意参与者注入；更大范围的协调不能由这份示例冒充完成。

## 兼容与安全

稳定 ID 不检查字段布局、版本或授权。原始 unmanaged 内存可能包含指针或进程本地句柄，不能直接序列化；M4 必须定义 codec 与兼容性验证。目录不消费未认证网络数据、不执行反射或动态代码。

目录属于当前运行时初始化产物；创建线程配置、冻结后共享。冻结时内存不足会正常抛出，代码结构保留可重试状态，但真实 OOM 恢复尚未动态验证。
