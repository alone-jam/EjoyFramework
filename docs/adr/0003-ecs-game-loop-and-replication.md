# ADR 0003 — ECS 固定 tick、生命周期与有界预测机制

Status: Accepted for implementation; current code statically reviewed, runtime acceptance pending (2026-10-03)

## Context

WS5-M3 需要分阶段模拟、固定 tick、同步点销毁、复制/预测/插值契约，以及按 cell 集成流送。用户确认了 `in EcsTime` 的接口迁移、默认固定 30Hz 加插值、Core→Core.Ecs 的流送桥依赖；ECS 内核继续自研，不引入 Unity.Entities。

本记录以当前代码为准，替代恢复资料中尚未实施的草案假设。参考 Unity FPSSample 的显式游戏循环、延迟销毁与复制分类，但不照搬其反射发现、每实体序列化器对象或无上限追赶。

## Decision

1. **时间与调度**：TickClock 默认 30Hz，消费时推进 tick，限制每帧追赶并保留余量 Alpha。ISystem 接收 readonly EcsTime；SystemGroup 保留帧时间便捷入口。EcsLoop 分离 tick 模拟与帧表现，Unity 驱动在 Update 中累积固定 tick，旧 FixedUpdate 配置映射到新路径。
2. **销毁与查询**：请求销毁立即从默认查询排除，但组件保留至清理同步点。每轮清理先固定批次，新请求进入后续轮；每同步点最多四轮。独立组在成功结束后释放请求；循环运行专门的 Despawn 阶段。结构变化仍受遍历守卫保护。
3. **访问与容量**：struct 访问器复用原查询执行器并在异常时写回访问器状态。实体/组件容量可显式预留；组件类型采用进程内泛型编号，但该编号不进入协议。数组扩容准备完成后一起发布。
4. **组件身份**：每次成员新增生成不复用的 lifetime，普通值写入不改变。该标记与 World、类型及完整 Entity 一起用于状态访问失效，不是网络 ID 或变化 tick。移除重加后旧基线和历史绑定自动不可用，重新 Bind 后接收新状态。
5. **状态分类**：冻结的 ReplicationSchema 使用显式非零 schema ID。权威最新基线、远端插值历史、本地可截断预测历史保持各自语义；均拥有值副本并校验绑定/时间线。Schema 不是字段 codec，unmanaged 不是原始字节线格式许可。
6. **采集与恢复**：TickCompletedSink 逐个观察完成 tick，非强制只读视图。单/双组件精确恢复在写前校验 tick、身份与 lifetime。调用方仍要保证统一权威来源和完整依赖范围。
7. **显式重放**：只重放 opt-in tick 系统，保持真实时钟不变；结构操作被拒绝，值命令正常回放。采集前后检查所有自有缓冲，防止向跳过阶段泄漏延迟命令。异常保留已发生的值修改并要求显式恢复，不声称事务回滚或 IO 沙箱。
8. **流送桥**：桥位于 Core，Core.Ecs 仍无程序集依赖。每次加载保留独立分区键，生成与新销毁请求分别受预算限制；实体实际清理后才卸载 IO。取消/失败不向持久化层伪报成功。旧 cellId-only 回报必须恰好一次，无法识别复用后旧重复回报。

## Consequences

- 游戏宿主的 ISystem 实现、驱动注册和复制的示例要同步迁移；本机没有宿主副本，不能将仓库内迁移视为宿主已编译。
- 普通 ECS 组件仍可含托管引用；复制存储要求 unmanaged，但原生资源/指针的所有权仍由应用负责。
- 固定 tick 与重放资格不自动保证跨平台确定性，不能不经验证就声称锁步可用。
- 封闭纠错示例只拥有一个实体、两个完整状态组件和精确输入环。示例采用 8Hz 整数模拟，不改变框架默认 30Hz，也不代表多实体通用协调器。
- 会话/权威 epoch、网络实体身份、字段布局版本、输入准入、完整快照/差分、AOI 和网络纠错调度属于 M4，见 ADR 0004。完整应用必须覆盖所有重放系统的状态依赖。

## Validation status

上述代码、测试和示例已按切片独立静态审查，确认的问题已修复并复核。M2/M3 改动已汇入同一开发 worktree，但**未进行当前合流版本的编译、Unity 全量测试或目标平台性能验收**，未合入 main。路线图保持未勾选，具体记录见 `Tools~/Ecs/VALIDATION.md`。
