# Linear projectile consumption contract

EjoyArena's Terraformer GooRocket loop required three reusable mechanisms, implemented in the existing platform-independent Combat assembly:

- `LinearProjectileWorld`: bounded owner-thread straight-flight state, stable spawn identity, complete previous-to-current segment sweeps, explicit missing-history/latest fallback policy, one impact transition, retained impact state and flight/impact expiration. The last movement query resolves before age-based removal, so a boundary impact enters retained state. Damage, team mask and authored tuning are caller policy. It has no Unity physics, callbacks or damage rules.
- `HistoricalHitWorld.OverlapSphere`: exact sphere/capsule/rotated-box overlaps at an explicit frame, deterministic unique-owner results with lifetime identity, mask/exclusion and force-inclusion. No implicit temporal fallback; output must cover the configured collider capacity. No occlusion/line-of-sight policy is invented.
- `ProjectileReplicaSet`: bounded complete-frame prediction confirmation/correction, strict session and monotonic frame boundaries, once-only impact notification, rejection of absent past predictions, generation retirement and timeout/reset cleanup. Matching type/owner/generation/start tick plus trajectory tolerance confirms the existing view. Changed geometry corrects it. The caller owns visual assets, playback and frame codecs.

Replica inputs must be **complete** projectile frames. New authority objects must be included from their spawn frame onward while retained; a later frame cannot introduce a launch already omitted in an applied earlier frame. Impact retention is not a durable event stream: a long network outage can miss an expired explosion. Timeout hides a view but retains bounded identity until the next complete frame/reset so a late impact state does not replay an already displayed explosion. Capacity exhaustion is explicit, never silent truncation. Caller must validate the network session before passing the frame; tokens are not authentication.

The game preserves the reference's current-character-center splash falloff after historical shape selection. Full animated hitboxes, map, original first-person weapon and projectile art/audio remain consumer limitations. The framework does not copy game damage numbers, ability arbitration, score rules or proxy visuals.

Tests cover high-speed thin-target tunneling, moving historical targets, no repeat impact, strict impact expiry, unavailable history and explicit fallback, owner deduplication/team/self masks, confirmation/correction, duplicate/reordered frames, timeout, old session and respawn generation, transactional malformed frames and warm zero managed allocation for flight/overlap. The process probe's `--authority-blackout` drops server data for four seconds (age 2.5..6.5) to force visible prediction timeout and later reconciliation; `--drop-disconnects` forces lost-Bye reconnect coverage.

## Relationship to preceding weapon work

PR #11 introduced `PredictedEventLedger`, a bounded event reconciliation primitive: speculative starts, complete authoritative event windows, confirmation, authoritative-only events, rejection, history expiry and scope reset/close. It did not introduce projectile trajectories, persistent replicated object views, historical overlap, audio pooling or ability rules. Existing tick prediction suppresses replay effects; EjoyArena added deterministic complete rifle state and routes cues through the ledger and framework sound helper.

PR #12 separately fixed UDP candidate reconnect after a lost Bye and tick-session disconnect-before-replacement admission ordering. It added no weapon/flight logic. This iteration consumes both changes; it does not substitute for their event-ledger or reconnect regressions. Each consumer evidence stage retains the failures it discovered.

The first real player run also exposed the interval between transport peer removal and its deferred disconnect callback: application membership can still include a peer that closed during Poll. `UdpNetTransport.TrySend` provides explicit false admission for an unavailable peer; validation errors/backpressure still throw for connected peers. The new transport test verifies this interval. This complements, rather than changes, the existing deferred callback contract. The game must construct thread-owned services in Start, not MonoBehaviour field initialization on Unity's loader thread; the initial failed run is preserved.


## Render-frame catch-up and fallback provenance follow-up

A consumer graphical hitch could apply a fresh mouse sample to the first of many elapsed catch-up ticks. The speculative launch could therefore precede server receipt (observed predicted 1020 vs authority 1023); a later isolated run passed without a code fix, so that retry alone did not establish resolution. `TickPredictionCoordinator.PlanFrame` provides bounded chronological simulation with a single current sampling tick. Earlier ticks keep the preceding held command; a budget-limited batch that cannot reach the target must leave current input pending. This does not change reconciliation, command admission, history contents or forward-only effects. The caller still chooses authority clock, lead, buttons and sampling adapter. Tests exercise state, retained commands, complete send range and correction replay after a hitch.

Projectile results now distinguish future and unavailable-past fallback queries. Each impact retains both requested and effective query ticks; callers can distinguish query counts from actual fallback hits. Latest-history fallback remains explicit and caller-selected; it does not claim equivalent hit fairness to the displayed historical state. FPSSample GetHistoryIndex similarly selects the latest state for future/out-of-window requests (original history count 16). The current consumer's 64-frame capacity is a documented difference; counts must never be hidden by reporting thresholds.

PR #13's swept motion and replica lifecycle were merged before these follow-ups. Its consumer had independent probe passes but open normal-window and moving-combat acceptance; the combined failures remain preserved. Framework .NET session 112/112 and collision/projectile 25/25 passed for this increment; Unity results are recorded in the PR.


## Authored Unity rigs and static maps

UnityHistoricalColliderCapture converts disabled authored bone-attached sphere/capsule/box colliders into value history without live physics side effects. It preserves owner/generation/subshape/tag, scale and orientation; unsupported shapes, degenerate transforms and sheared boxes/capsules fail explicitly. The game owns source rigs, clip selection/evaluation and which pose/tick to capture.

IHistoricalSweepQuery allows immutable static geometry to participate alongside history. StaticPhysicsHistoricalQuery composes an explicit static-only Unity physics layer with HistoricalHitWorld, selecting the closest static mesh or historical dynamic hit. Wrong epoch/missing history remain visible so fallback is still the caller's decision. It handles initial sphere overlap and validates registered collider transforms/enabled/layer state per captured tick. Caller must keep static mesh topology and scene immutable; rebuild the adapter on scene changes. Mesh hits carry an ExternalStatic identity that cannot be inserted into primitive history frames. No arbitrary mesh bounds approximation or game-side collision replacement is used.

Unity regression coverage includes animated pose/lifetime capture, three capsule axes, rotated boxes/shear rejection, static mesh occlusion, exclusions/epoch/history admission, fast projectile collision, initial overlap and moved-static rejection. Full Unity: 3526 passed/8 skipped/zero failed; .NET collision 25/25. The final layer/trigger validation guard was followed by the three static-scene tests. This does not implement moving/deforming mesh rewind.

The first consumer player rejected the static map during registration although Editor tests passed: an editor/baking `GameObject.isStatic` prerequisite is not a reliable player-time immutability contract. The adapter now relies on explicit registration plus runtime transform/enabled/layer validation; unbaked geometry is covered by the static scene tests. The failed player report is retained in the consumer, and no game-side bypass sets fake baking flags.
